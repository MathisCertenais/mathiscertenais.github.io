# Coding standards

What a reviewer enforces on a diff in this repository. `AGENTS.md` holds the product rules; this
file holds the engineering ones. When the two disagree, `AGENTS.md` wins.

## Formatting

- TypeScript and TSX: single quotes, **no semicolons**, two-space indentation, trailing commas in
  multi-line literals, about 100 columns.
- Named exports only. No default exports for components or modules.
- Imports: external packages first, then local modules, then styles; `import type` for types.
- Run `pnpm lint` and `pnpm typecheck` before claiming a change is ready. ESLint uses the
  type-aware ruleset (`recommendedTypeChecked`): `any`, unsafe member access and floating
  promises are findings, not suggestions.

## TypeScript

- `strict` is on. No `any`, no non-null assertion to silence a real null, no `@ts-expect-error`
  without a comment explaining what would fix it.
- Content and configuration are typed at the source: `as const` for fixed data, exported
  interfaces for structures that cross files (`ArticleItem`, `ArticleBlock`, `ResearchChapter`).
- A closed set of ids is a union (`ArticleId`), not `string`. Adding an article means extending
  the union — the compiler is the checklist.
- Prefer plain functions and data over classes; no enums (`const` objects and unions instead).

## React

- Function components, one component per file, named after the file.
- `App.tsx` and `routing.ts` own routing; components do not read `location` directly. Use
  `useAppLocation()`.
- Content comes from `src/content/` and `src/locales.ts`; a component never hard-codes user-facing
  prose. If a string is visible, it is translatable.
- Language and theme are context providers (`src/language/`, `src/theme/`). Do not duplicate
  their state locally.
- Effects are for synchronisation with the browser only. Derive state; do not mirror props into
  state.
- Every interactive element is a real `button` or `a`, with an accessible name. No clickable
  `div`.
- No `dangerouslySetInnerHTML`. Inline article links are parsed from `[label](url)` in
  `text`.

## CSS

- One stylesheet, `src/styles.css`, organised with `@layer`. Add to the existing layer rather
  than creating a new architecture.
- Colours, radii, spacing and fonts come from custom properties in `:root`. A new literal colour
  in a component rule is a review finding unless it is a documented one-off (for example the
  business card's print palette, which is intentionally independent of the theme).
- Both themes must be checked: light, dark, and `prefers-color-scheme` before an explicit
  choice. Never signal state by colour alone.
- Mobile-first, `min-width` media queries, `min-width: 320px` must work without horizontal
  scrolling.
- Respect `prefers-reduced-motion` for every transition that moves or fades more than a token
  amount.

## Content and routes

- `src/content/en.ts` is the source of truth. `fr.ts` translates it; it never introduces a fact
  that the English does not contain.
- Adding or changing a page means: content in both languages, strings in `src/locales.ts` in
  both languages, and entries in `src/data/route-manifest.json` (canonical, French variant if the
  page is public in French, legacy alias if an old URL pointed there).
- Titles and descriptions in the manifest are unique per route and describe the page, not the
  site. `check:routes` fails on duplicates and on routes whose `page` id has no content.
- Public assets must be referenced by content or the route validator rejects them. Do not leave
  an orphan image in `public/`.
- `dist/` is regenerated by `pnpm build`, never edited. Commit it in the same change as the
  source that produces it.

## Accessibility gates

Before a UI change is called done:

- Keyboard: every control reachable in a sensible order, focus visible, no trap.
- Semantics: one `h1` per page, heading order preserved, landmarks (`main`, `nav`, `footer`),
  skip link intact.
- Names: every image has `alt` (decorative images use `alt=""`), every icon-only control has an
  `aria-label`, every form field has a `<label>`.
- Announcements: dynamic status (form result, copied confirmation) uses `aria-live` and does not
  steal focus.
- Contrast: 4.5:1 body, 3:1 large text and control boundaries, in both themes.
- Zoom and reflow: 200 % zoom and 320 px width, no horizontal scroll, no clipped text.

`docs/rgaa-audit.md` records what has been verified and what is declared partial. Do not claim
conformance beyond it.

## Checks and delivery

| Command | What it proves |
| --- | --- |
| `pnpm lint` | ESLint, zero warnings |
| `pnpm typecheck` | `tsc -b`, no errors |
| `pnpm check:routes` | manifest ↔ content ↔ public assets |
| `pnpm build` | the site builds and every route is prerendered |
| `pnpm check:dist` | each shell has its title, description, canonical and body |
| `pnpm check` | all of the above, in that order |

- A change is ready when `pnpm check` passes with the production origin:
  `VITE_SITE_URL=https://mathiscertenais.com pnpm check`.
- The pre-push hook enforces the same three conditions as CI: checks pass, the working tree is
  clean (except `tasks/`), and `dist/` matches a fresh build.
